# ADR-0002: Использовать PostgreSQL как основную БД

## Статус
Принято — 2026-07-07

## Контекст
Нужна реляционная БД для строго структурированных сущностей (users, workspaces, projects, tasks) со связями многие-ко-многим (участники, теги, назначения), плюс потребность в гибких полях (метаданные AI-запросов) и, в перспективе, полнотекстовом поиске.

Рассматривались: MySQL, PostgreSQL, MongoDB (документная альтернатива).

## Решение
Используем **PostgreSQL 16**.

- Данные предметной области реляционные по своей природе (задача принадлежит колонке, колонка — доске, доска — проекту) — документная модель потребовала бы денормализации и ручной поддержки согласованности.
- `JSONB` закрывает потребность в гибких полях (`AI_REQUESTS.input_payload/output_payload`) без ухода от реляционной модели целиком.
- Встроенный полнотекстовый поиск (`tsvector` + GIN-индекс) — не нужен отдельный Elasticsearch для Roadmap-фичи поиска.
- Зрелая интеграция с SQLAlchemy 2.0 async + Alembic.

## Последствия
- Полнотекстовый поиск Postgres слабее специализированных движков при очень больших объёмах данных — если проект вырастет за пределы портфолио, это точка для миграции на Elasticsearch/Meilisearch, но не для MVP.
- Требует управляемого экземпляра Postgres в проде (учтено в docker-compose и production-топологии, раздел 8).
