# ADR-0001: Использовать FastAPI как web-framework

## Статус
Принято — 2026-07-07

## Контекст
Нужен Python web-framework для REST API + WebSocket с async I/O, строгой валидацией входных данных и автогенерацией API-документации (важно для портфолио — рекрутер должен иметь возможность открыть `/docs` и сразу увидеть контракт).

Рассматривались: Django REST Framework, Flask + расширения, FastAPI.

## Решение
Используем **FastAPI**.

- Async-first из коробки — не нужен отдельный слой типа Django Channels для WebSocket.
- Нативная интеграция с Pydantic v2 — валидация запроса/ответа без ручного написания сериализаторов (в отличие от DRF).
- Автогенерация OpenAPI/Swagger UI — бесплатная живая документация API.
- Dependency Injection через `Depends()` — естественно ложится на Service Layer + Repository Pattern без дополнительного DI-фреймворка.

## Последствия
- Экосистема младше, чем у Django (меньше готовых пакетов "из коробки" — админка, ORM-миграции идут отдельно через Alembic).
- Вся авторизация, RBAC, rate limiting пишутся руками или через сторонние библиотеки — осознанный выбор, так как даёт полный контроль над контрактом API.
- Требует дисциплины в организации кода (FastAPI не навязывает структуру проекта) — компенсируется модульной структурой из раздела 2.2 основного документа.
